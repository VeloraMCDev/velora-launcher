# First typed execution policy

The Milestone 5 executor permits only the stateless Development probe. A signed
job binds its UUID, deployment UUID, agent identity, environment, service, exact
GHCR image digest, expected source revision and five-minute admission window.
Worker Web Crypto and native Rust verify the same synthetic signature fixture.
Unknown fields, commands, other services/environments, tags and alternate registries
are rejected. Real signing keys are not generated by implementation/test tools.

The source-stamped Linux agent binary has a host-local entry point:

```sh
velora-agent probe-execute --policy /etc/velora-probe/policy.json --job /path/to/signed-job.json
```

This entry point is an implementation building block, not a deployed normal
delivery path. Normal deployment must use the protected control plane, durable
Workflow and native agent job transport. SSH remains bootstrap/recovery only.
The new [Development orchestration and transport](../../control-plane/PROBE_DEPLOYMENTS.md)
provide reservation, signed polling and authenticated results in local runtime
tests. Privileged host installation and the live execution proof remain pending.
The heartbeat daemon does not execute jobs, advertise new capabilities or gain
Docker membership merely because this code is installed.

The caller needs the existing host-local Docker client/socket permission. Production
installation must put this policy behind a reviewed narrow local executor boundary;
never grant broad Docker access to the heartbeat agent or expose its socket over
the network. The policy's trusted public key and target agent are operator-bound;
an empty example policy is deliberately unusable. Signing private keys stay in
the control plane secret store, never in jobs or on the execution agent.

Compose topology is generated from fixed code: one labelled container, an isolated
project-scoped default network (never `internal`: Docker cannot publish ports from one, so the host health check would fail), loopback-only `127.0.0.1:18985`, no host mounts, read-only root,
non-root UID, dropped capabilities, bounded memory/CPU/PIDs and temporary storage.
An existing container without the exact ownership label is never replaced.
There is no shell or operator-supplied command, environment, path, port or Compose
document in a signed job. Pull and activation are bounded; health must match the
expected source revision for thirty seconds.

Private host-owned state contains an OS-held deployment lock, checksummed job
identity receipts, fixed Compose document and the previous known-good job.
Successful duplicate requests return the stored receipt without invoking Docker.
Conflicting identities fail. An interrupted nonterminal receipt returns BLOCKED
for reconciliation rather than claiming success or repeating side effects.
Failed health restores the previous exact image and checks its identity. No
database, volume or production restoration is part of this policy.

Tests cover signature/target/expiry/image policy, fixed topology, lock contention,
state ownership/symlinks, idempotency and previous-digest rollback with an injected
test-only runtime. Docker and live control-plane integration remain separate
Milestone 5 gates until the real chain has passed. No Hermes workload has been
activated by these tests.
