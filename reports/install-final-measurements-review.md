  of different families/runs was observed.

The summary's final `AUDIT_OK` line is a status terminator, not another metric;
the request table is separate from the timing tables. The audit explicitly
distinguishes these structures. Three-decimal comparisons use scaled decimal
rounding (`Math.round(value * 1000) / 1000`), rather than assuming JavaScript's
binary `toFixed` resolves exact half cases identically. For example, raw final
hash median **4.8965 ms** is displayed as **4.897 ms**; this is an ordinary display
rounding convention, not a raw-data mismatch or hidden regression.

Recalculation algorithm (five samples in each metric/run):

```javascript
const median = (samples) => [...samples].sort((first, second) => first - second)[2];
const summarize = (samples) => {
  const center = median(samples);
  return {
    median: center,
    minimum: Math.min(...samples),
    maximum: Math.max(...samples),
    mad: median(samples.map((value) => Math.abs(value - center))),
  };
};
```

MAD is unscaled median absolute deviation, not a confidence interval. Installation
values come from each family's `elapsed_ms`; isolated helpers and process times
come from the native family's `helpers`/`jvm` fields. Units are milliseconds.
